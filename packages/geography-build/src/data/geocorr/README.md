# Vendored Geocorr 2022 exports

Two files from the **Missouri Census Data Center (MCDC) Geocorr 2022** correlation engine,
2020-vintage geographies, covering the crosswalks named in ADR-008 §2 / issue #55. Geocorr has
no API and no stable download URL, so its exports are vendored here (ADR-008), loaded by
`vendored.ts`, and read by `../../parse/geocorr.ts`.

Retrieved **2026-09-17**, `wtvar=pop20`, all 52 states/DC/PR, `nozerob=1`. SHA-256 `6224d2ec2edf670aa1cc4ad4de5bcf3016352701342d3bd39a54753934386836`. |
| `geocorr2022_sample.csv` | `cousub_cbsa`, `zcta_tract` | 5 | Hand-picked slice for fixtures and a few well-known crossings (Hartford, Cambridge, ZCTA 19104/02134). |

## Why place↔county is national and the others are a sample

Census publishes **no** 2020 place↔county relationship file (`../../download.ts`), so Geocorr is
the *only* source of that edge — and it is the edge the LAUS below-threshold county fallback
(ADR-009 §6, the product's core value) depends on. Until #141 the repo shipped a 7-row sample
here, which left the fallback empty for every city except Atlanta and NYC. The regression test
`vendored.test.ts` asserts the national file resolves Sedona, AZ → Yavapai County (0.737) and
that every place's allocation factors sum to 1.

The other two pairs are covered elsewhere (`zcta_tract` by a downloaded Census relationship file;
`cousub_cbsa` is not yet consumed by any tool), so the sample suffices for them.

## Regenerating the national file

`npm run geocorr:fetch -w packages/geography-build` replays the Geocorr form against its SAS
broker (`GET https://mcdc.missouri.edu/cgi-bin/broker`) with the **complete** field set — the job
fails with a `%EVAL` macro error if any form field is omitted, even blank text inputs — and with
all 52 `state` values (the "entire United States" is the multi-select, not a single code). It
then transforms the broker's native columns (`state, place, county, stab, CountyName, PlaceName,
pop20, afact`, two header rows) into the vendored schema below (`transformGeocorrPlaceCounty`),
gzips, and prints the row count and SHA-256 to record in the table above. The broker's output
link is a scratch `/temp/` path, not a stable URL, which is why the result is vendored rather
than downloaded at build time. Moving this file to a hosted mirror is on the M7 data-mirrors
spike (#51).

## Columns (vendored schema)

| Column | Meaning |
|---|---|
| `geo_pair` | Which crosswalk this row belongs to: `place_county`, `cousub_cbsa`, `zcta_tract`. |
| `child_geoid` | The Census GEOID of the "target" geography in `containment.child_geoid`. |
| `child_name` | Human-readable name, for spot-checking. Not loaded into the catalog. |
| `parent_geoid` | The Census GEOID of the anchor ("source") geography in `containment.parent_geoid`. |
| `parent_name` | Human-readable name, for spot-checking. Not loaded into the catalog. |
| `afact` | Geocorr's population-weighted allocation factor: the fraction of the anchor's 2020 population in the target's slice. Loaded directly as `containment.share`. |
| `pop20` | The 2020 population of the intersection, for reference. Not loaded. |

For `place_county` the anchor is the **place**: `afact` is the share of the place's population in
each county (Atlanta → 0.9198 Fulton / 0.0802 DeKalb), so shares sum to 1 per place and the
LAUS fallback picks the majority county.

## Precedence

Geocorr's `afact` is **population-weighted** and is the authoritative `share` wherever it covers
an edge; the Census relationship files (`parse/relationship.ts`) are **area-weighted** and are
the fallback everywhere Geocorr has no row. `assemble.ts` dedupes by `(child_geoid,
parent_geoid)` and lets a Geocorr row win over a relationship-file row for the same edge.
