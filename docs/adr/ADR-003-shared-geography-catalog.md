# ADR-003: A build-time SQLite geography catalog and one resolver for the whole family

**Status:** accepted (2026-09-08) · **Spike:** [`geography-catalog`](../spikes/geography-catalog.md) ·
**Affects:** `packages/core/src/geography`, `packages/geography-build`, every server

> **Amended by ADR-008 (2026-09-09):** §1 (bundled-only) now also ships a hosted
> `server-geo`; §3 (single vintage) gains a tract-lineage table; the resolver's caveats
> become structured flags. The catalog design below otherwise stands.

## Context

No published reference reconciles the geographic nomenclatures of federal statistical
programs. The same Denver metro is CBSA `19740` to Census, `MT0819740000000` to LAUS,
`0019740` to OEWS, `C1974` to QCEW and `S48B` to CPI. The spike catalogued the public
domain sources that, joined, give a place → every-identifier lookup plus the containment
hierarchy and which level each program publishes at. The owner accepted the spike's
recommendations on its six decision questions on 2026-09-08.

## Decision

1. **One catalog, built at build time, shipped read-only.** A versioned SQLite file
   generated by `packages/geography-build` from: Census Gazetteer and `geoinfo` entity
   lists, the 2020 ANSI place-by-county file, OMB 2023 delineation lists, Census 2020
   relationship files, BLS LABSTAT area code tables (`la`, `sm`, `oe`, `cu`) and QCEW
   area titles, a vendored Geocorr 2022 export, and a hand-maintained county-change
   table. Tables: `entity`, `alias`, `containment`, `agency_code`, `publishes_at`,
   `county_change`.
2. **Tracts are included** (≈30 MB total); the Lambda cold-start cost is acceptable.
3. **Single current vintage plus a `county_change` translation table.** Full
   multi-vintage entity rows are deferred until a time-series question needs them.
4. **Geocorr is vendored** for population-weighted allocation shares; Census relationship
   files alone give only area shares.
5. **Wikidata aliases are deferred.** Gazetteer names plus a small hand alias list cover
   Release 1.
6. **Every envelope carries GEOID, UCGID and the Data Commons DCID** for the resolved
   place, since DCIDs are GEOIDs and the interoperability is free.
7. **Ambiguity stops the call.** When the top candidates differ in kind (city vs county
   vs metro) and the caller gave no kind, `resolve_place` returns `status: ambiguous`
   with the candidates and a one-line explanation rather than guessing.
8. **Only core resolves places.** No server ships its own name lookup or FIPS table;
   agency codes are columns on the shared catalog. The contract suite enforces this.
9. **The model gets a reference too.** A `geography://guide` resource (and the same text
   in `describe_source`) explains summary levels, non-nesting geographies, city vs
   county vs metro, ZCTA vs ZIP, and which level each program publishes at. Resolver
   output carries `kind`, `parents`, `available_at` and `caveat` per candidate.

## Consequences

- The catalog is the first real dependency of every server; it is its own milestone (M2)
  with its own reproducibility gate in CI.
- Redelineations (OMB), county changes and BLS program adoptions require a catalog
  rebuild and a version bump, not code changes.
- Denver-style same-name city/county pairs, consolidated-city "balance" places, CDPs,
  the LAUS 25,000 threshold, NECTA retirement and the Connecticut planning regions are
  handled in data and resolver tests, not in prompts.
